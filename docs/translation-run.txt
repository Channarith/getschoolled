COURSE TRANSLATION ON LOCAL MACHINES (free NLLB-200)
====================================================
Plain text on purpose (repo no-markdown house rule).

Why: salareen.com serves English text for other languages because few courses
have a stored translation and production has no translator. Translating with a
paid API is costly (about 96 million words for 948 audio courses x 26 languages),
so we run the free NLLB-200 model on our own machines.

Split (no overlap, so the two folders merge cleanly):
  DGX Spark   : es fr de it pt nl pl ru uk tr ar he hi bn ur fa zh ja ko vi
  iBuyPower   : th id sw el cs km
If the iBuyPower has no NVIDIA GPU, give it fewer languages or only the demo
course (edit IBUY_LANGS in scripts/translate_on_machine.sh).

On each machine (Cursor terminal, repo root):
  scripts/translate_on_machine.sh setup
  scripts/translate_on_machine.sh test          # demo course, es + km; check the text
  scripts/translate_on_machine.sh run spark     # on the Spark
  scripts/translate_on_machine.sh run ibuy      # on the iBuyPower
  scripts/translate_on_machine.sh status

Run in the background with: nohup scripts/translate_on_machine.sh run spark > ~/batch.log 2>&1 &
Rerun the same command after a stop or reboot; finished files are skipped.

Merge: rsync -a one machine's ~/translations/ onto the other. Files never collide.

Notes:
  - Output folder: AOEP_COURSE_TRANSLATION_DIR (default ~/translations).
  - Device policy (aoep_shared/devices.py): on the DGX Spark CUDA is REQUIRED. NLLB_DEVICE=cpu and an
    empty CUDA_VISIBLE_DEVICES are ignored there with a loud warning unless AOEP_ALLOW_CPU=1 is also set,
    and a missing or broken CUDA fails fast instead of falling back to the CPU. On the iBuyPower CUDA is
    preferred and CPU is allowed. The gateway reports the device in use at GET /device (503 when the
    policy is violated) and in the "device" field of /translate. A CUDA failure on the Spark returns 503
    from /translate; it is never turned into a phrasebook or passthrough answer.
  - NLLB runs in batches (NLLB_BATCH_SIZE, default 16; NLLB_NUM_BEAMS, default 4; NLLB_DTYPE bf16|fp16|fp32,
    default bf16 on CUDA). A GPU only helps when it is fed batches. The speed-up on the Spark is
    UNMEASURED: run scripts/nllb_bench.py on each device and compare before relying on any number.
  - CONCURRENCY=N changes parallel jobs (default 4).
  - Khmer, Swahili and Bengali are weaker in NLLB; spot-check before shipping.
  - Course Studio courses are not included (script flag --audio-only); rerun
    scripts/translate_courses_batch.py without it later.
  - Next step after merging: ship the folder to production (volume or object storage).
