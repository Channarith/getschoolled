SALAREEN TTS BAKE-OFF: PICK THE VOICE-AGENT TTS ON EVIDENCE
===========================================================
Plain text on purpose (repo no-markdown house rule). Code is in tts_bakeoff/.

DECISIONS FROM THE OWNER (2026-10-24)
  1. License: the product shortlist may only contain models whose WEIGHTS and CODE allow commercial use.
     Non-commercial models may be run internally as reference baselines, labelled NOT SHIPPABLE.
  2. Goal: the best natural voice PER LANGUAGE, not one cloned voice across languages.
  Priority languages: Khmer (km), Vietnamese (vi), Thai (th), Spanish (es), English (en), Mandarin (zh),
  then Swahili (sw), Hindi (hi), Bengali (bn). The app ships 27 languages; the other 19 come later.

WHAT THE RESEARCH FOUND (details and URLs with retrieval dates: tts_bakeoff/candidates.yaml)
  Fish Speech V1.5 is NOT a candidate for the product: its weights are CC-BY-NC-SA-4.0 (non-commercial)
  and it covers 13 languages, none of Khmer, Vietnamese, Thai, Swahili, Hindi or Bengali. The same is true
  of OpenAudio S1-mini (CC-BY-NC-SA-4.0). It stays in the harness only as an internal reference.
  CosyVoice 2 (our current stack) is Apache-2.0 but covers zh, en, ja, ko, de, es, fr, it, ru: no Khmer,
  Vietnamese, Thai, Swahili, Hindi or Bengali. So its Khmer needs our own fine-tune data, which is slow.

  Per hard language, commercially usable options found:
    Khmer       VoxCPM2 (Apache-2.0, open, claims Khmer). Cloud: Azure (standard neural voices Sreymom, Piseth).
                Every other open Khmer model found is non-commercial (MMS-TTS CC-BY-NC, F5-TTS Khmer demos
                CC-BY-NC). KLEA is MIT but single words only. So: one open candidate, and it is new.
    Vietnamese  VoxCPM2; NVIDIA Magpie TTS Multilingual 357M (NVIDIA Open Model License, card says ready for
                commercial use; read the license itself; Blackwell GPUs not in its supported list);
                MOSS-TTS v1.5 (sources conflict, see below). Cloud: Azure, ElevenLabs Flash v2.5.
    Thai        VoxCPM2; MOSS-TTS v1.5 (unverified). Cloud: Azure. Nothing else found.
    Swahili     VoxCPM2; Chatterbox Multilingual (MIT); MOSS-TTS v1.5 (unverified). Cloud: Azure.
    Hindi       VoxCPM2, Chatterbox, Magpie, Kokoro (code license still to confirm). Cloud: Azure HD, ElevenLabs.
    Bengali     NO open commercially usable model found. Cloud only: Google Chirp3-HD (bn-IN), Azure (standard).
    es / en / zh  plenty: Qwen3-TTS, CosyVoice 2, Kokoro, MeloTTS, Chatterbox, VoxCPM2, Magpie.
  VoxCPM2 is the standout because it is the only open, Apache-2.0 model claiming Khmer, Thai, Vietnamese
  and Swahili together. Its quality figures (km CER 2.05%, th 0.94%, vi WER 1.56%, sw 1.07%) are the
  authors' own, measured with Gemini as the ASR on their internal set. A separate complex-text study
  reported much higher error on Thai, Vietnamese and Swahili. The bake-off exists to check this on OUR text.

NOT VERIFIED (do not rely on these until confirmed)
  - Code licenses for Qwen3-TTS and Kokoro were not read from their repositories, so they are not counted
    shippable. Fish Speech's code license was not read either (irrelevant: its weights are non-commercial).
  - XTTS-v2 (Coqui CPML): the license page returned 404; treated as not shippable.
  - MOSS-TTS: the GitHub README lists Thai, Vietnamese, Swahili, Hindi for v1.5; the Hugging Face card read
    lists 20 languages without them. Test the v1.5 weights before believing either.
  - Training-data provenance is unverified for EVERY model. Apache or MIT on the weights does not remove
    a possible data-licensing question; ask the vendors or get legal review before a launch.
  - Spark GB10 (aarch64, CUDA 13) support is unverified for every new model. Try them early.
  - Pricing for Azure, Google and ElevenLabs was not retrieved.
  - The Khmer, Thai, Swahili and Hindi test sentences are authored translations, unreviewed by native speakers.
  - Adapters were written from vendor documentation and tested with a mock model only. No GPU or real
    weights exist in the build sandbox. Run the --check step on the target machine first.

THE HARNESS
  tts_bakeoff/candidates.yaml   license + coverage + hardware matrix, with evidence per claim; schema.py validates it
  tts_bakeoff/sentences/*.jsonl 40 sentences per language (short, medium, long, numbers, dates, names, vocab,
                                questions) from our course domain; deterministic; regenerate with build_sentences.py;
                                --limit N always returns a mix of categories
  tts_bakeoff/adapters/         one file per model: check() and synthesize(text, lang, out_wav); heavy imports are lazy
  run_bakeoff.py                synthesize one model, resumable, writes manifest.jsonl and meta.json
  score_bakeoff.py              ASR round trip + audio sanity per clip, resumable
  report.py                     per-language leaderboard (HTML + CSV) with a license/shippable column
  panel.py                      blind listening panel generator + rating aggregator

  What the numbers mean
    ASR round trip: synthesize text, transcribe the audio, compare with the text. CER for km/th/zh, WER for the
    rest. Digits in the transcript are spelled out for en/es/zh; other languages drop digits and the report
    counts how many clips that affected. It measures INTELLIGIBILITY only. A weak ASR makes every model look bad
    in that language, so Khmer uses MMS and results must be read next to the human panel.
    Audio sanity flags: silent, clipped, dead air at the start or end, long pauses, speaking too fast or slow.
    Optional: a UTMOS naturalness score if its package can be loaded (never required).
    Human panel: native speakers rate naturalness and clarity 1-5 on anonymized, shuffled clips. The panel is
    what decides "best natural voice". The ASR score only screens out unintelligible models.

WHERE EACH PIECE RUNS (three machines; nothing here depends on scripts/gs_run.sh from the fleet-ops work)
  DGX Spark (GB10, 128 GB unified memory): GPU synthesis for the heavy models: voxcpm2, qwen3_tts,
    chatterbox, cosyvoice2, and fish_speech15 through its API server. One GPU job at a time.
  iBuyPower (RTX 5060 Ti 8 GB, 30 GB RAM, Python 3.14): light models (kokoro, mms_tts), and ASR scoring with
    faster-whisper large-v3 in int8 (fits in 8 GB). Several of these packages need Python below 3.13
    (VoxCPM2 needs 3.10-3.12): use a uv-managed 3.12 virtualenv, not the system 3.14.
  This Mac: reports, the listening panel, validation, and CPU-only runs of the tiny models. VoxCPM2 can also
    be smoke-tested on Apple MPS.

  Never starve a machine: run every long job in a resource scope and under the GPU lock, in the foreground, so
  nothing is left running afterwards:
    flock -w 600 ~/.gs-gpu.lock \
      systemd-run --user --scope -p MemoryMax=40G -p CPUQuota=800% \
      python3 -m tts_bakeoff.run_bakeoff --model voxcpm2 --langs km,vi,th,sw,hi,es,en,zh --out runs/2026-10-24
  On the iBuyPower use MemoryMax=20G. Servers started only for an adapter (Fish Speech API, CosyVoice server)
  must be stopped when the run ends:  kill $(cat server.pid)  then confirm with  ps aux | grep -E "api_server|cosyvoice".
  Before and after a run, check:  free -g ; nvidia-smi ; ps aux --sort=-%cpu | head. There must be no leftover or
  defunct process from the bake-off.

COMMANDS (run from the repo root; replace OUT with a dated folder such as runs/2026-10-24)
  Spark, once per model:
    python3 -m tts_bakeoff.run_bakeoff --model voxcpm2 --check
    python3 -m tts_bakeoff.run_bakeoff --model voxcpm2 --langs km,vi --limit 5 --out OUT       (smoke test first)
    python3 -m tts_bakeoff.run_bakeoff --model voxcpm2 --out OUT                                (full set)
    python3 -m tts_bakeoff.run_bakeoff --model chatterbox --langs sw,hi,es,en,zh --out OUT
    python3 -m tts_bakeoff.run_bakeoff --model qwen3_tts --langs es,en,zh --out OUT
    python3 -m tts_bakeoff.run_bakeoff --model cosyvoice2 --langs es,en,zh --option prompt_wav=PATH --out OUT
  Fish Speech 1.5 reference: start its API server, set FISH_SPEECH_URL, run --model fish_speech15 --langs es,en,zh.
  iBuyPower:
    python3 -m tts_bakeoff.run_bakeoff --model kokoro --langs es,en,zh,hi --out OUT
    python3 -m tts_bakeoff.run_bakeoff --model mms_tts --out OUT                  (the free Khmer/Thai/etc. baseline)
    python3 -m tts_bakeoff.score_bakeoff --out OUT --asr auto --device cuda
  Cloud ceiling (costs money; keep --limit small):
    AZURE_SPEECH_KEY=... AZURE_SPEECH_REGION=... python3 -m tts_bakeoff.run_bakeoff --model azure --langs km,th,vi,sw,hi,es,zh,en --limit 10 --out OUT
  Move results to the Mac:  rsync -a spark:~/code/getschoolled/OUT/ ./OUT/
  Mac:
    python3 -m tts_bakeoff.score_bakeoff --out OUT --asr auto        (or run it on a GPU machine)
    python3 -m tts_bakeoff.report --out OUT                         (OUT/leaderboard.html and leaderboard.csv)
    python3 -m tts_bakeoff.panel build --out OUT --langs km,vi,th --per-lang 8 --seed 7
    python3 -m tts_bakeoff.panel aggregate --out OUT ratings_*.json

RECOMMENDED ORDER
  1. Smoke-test VoxCPM2 on the Spark (5 sentences, km and vi). If it does not run on aarch64/CUDA 13, find out now.
  2. Run the full set for voxcpm2 and the mms_tts Khmer baseline, then score. If VoxCPM2 Khmer error is well
     below MMS and a Khmer speaker rates it natural, Khmer has a commercial path without fine-tuning CosyVoice.
  3. Run chatterbox (Swahili, Hindi), qwen3_tts and kokoro (es/en/zh), and the cosyvoice2 incumbent.
  4. Add the Azure ceiling for a small slice so we know the gap to a paid service.
  5. Build panels for km, vi, th first. Pick per-language winners from the panel, with ASR as a screen.
  6. Only then decide whether fine-tuning (VoxCPM2 LoRA for Khmer is reported in the literature) is worth the
     GPU time, and whether any model needs a legal read of its data terms before launch.

LISTENING LAB (hear and rate the voices side by side, on the Mac)
  1. On the Spark, run the bake-off and the scorer (commands above). Output lands in ~/runs/<date>/.
  2. On the Mac, copy it:  rsync -a nvidia@192.168.1.107:runs/2026-10-24/ ~/getschoolled/runs/2026-10-24/
  3. Open the lab:         python3 -m tts_bakeoff.lab --out runs/2026-10-24            (optional: --port 8765, --no-open)
     It serves the folder on 127.0.0.1 only (no network, no telemetry) and opens your browser.
  Try it without any run:  python3 -m tts_bakeoff.lab --demo     (synthetic tones, 3 voices, English and Khmer)
  Page without a server:   python3 -m tts_bakeoff.lab --export lab-page   then open lab-page/index.html and press
                           "Open run folder" to pick the run folder.
  Other voices (Azure, the old CosyVoice fine-tune): drag audio files or folders onto the page. Voice, language
     and sentence id are read from OUT/<model>/<lang>/<id>.wav, or a small form asks. Dropped voices are marked
     UNKNOWN LICENSE until they are in candidates.yaml.
  The grid has one row per sentence and one column per voice, with ASR error, speech rate and warnings from
  scores.jsonl. NOT SHIPPABLE voices (Fish Speech 1.5) are marked. Keys: space play/pause, arrows move, 1-5 rate
  naturalness, Alt+1-5 clarity, b blind mode, n/N next/previous sentence, Shift+letter play that voice, ? help.
  Blind mode shuffles the voices with a seed into A/B/C labels. Ratings are kept in the browser (localStorage).
  "Export ratings (panel JSON)" writes one file per language with its own key, so no panel build is needed:
    python3 -m tts_bakeoff.panel aggregate --out runs/2026-10-24 ratings_lab_*.json
  The Summary tab shows per-voice means, head-to-head wins and a verdict template; Reveal turns blind mode off.

  All platform languages plus extras (edge-tts, internal reference only; see docs/edge-voices-coverage.txt):
    python3 -m tts_bakeoff.snapshot_edge_voices                      # refresh tts_bakeoff/edge_voices.json (network)
    python3 -m tts_bakeoff.translate_sentences --dry-run             # cost estimate; needs XAI_API_KEY to run for real
    python3 -m tts_bakeoff.edge_all --out runs/2026-10-25-all --plan # clip count; drop --plan to render (resumable)
    python3 -m tts_bakeoff.lab --out runs/2026-10-25-all --port 8768
    python3 -m tts_bakeoff.coverage_report --run runs/2026-10-25-all
  The lab then has a searchable language picker (native names, right-to-left text for ar/he/ur/fa/ps), gender, accent and
  voice-type filters, voice groups with the style variants nested, "Compare these voices", and a per-language count of rated
  clips. --demo-edge serves synthetic tones in this layout without the network.
