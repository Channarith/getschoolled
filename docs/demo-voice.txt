Demo narration in a consented company voice
===========================================

What it is: the machine-vision (Vision Play), full-course and hidden On the Go demos can speak in a company voice
(first: channarith) chosen from a "Narrator voice" selector, default Salane. It is PRE-RENDERED audio, not live cloning.
Every clip is labelled "AI-generated voice of <name>" (VoxCPM2's licence asks for AI-generated labelling).

Pieces
  tts_manifest/voices.json              the selectable voices (id, label, speaker, model). Add a consented person here.
  tts_manifest/demo_voice_manifest.json what the demos say: demo, lang, text, hash. Regenerate:
        python3 -m tts_bakeoff.demo_voice.manifest [--extra-texts misses.jsonl]
  tts_bakeoff/demo_voice/clip_hash.py   clip id = cyrb53(lang + U+241F + NFC, whitespace-collapsed text), 14 hex. The same
        function is in apps/web/app/lib/cloneVoice.ts, apps/mobile/src/cloneVoice.ts and the Vision Play clone_voice.js;
        tts_manifest/hash_vectors.json is checked by pytest, node and jest so the three cannot drift.
  scripts/render_demo_voice.sh          on the Spark, under gs_run.sh --gpu: renders missing clips, resumable, shardable.
  python3 -m tts_bakeoff.demo_voice.verify   every manifest clip present for each active voice.
  scripts/sync_voice_assets.sh          uploads to object storage under voice-assets/ (never git; assets dir is gitignored).

Languages in the manifest: on_the_go in en, es, zh, vi, th, km, sw, hi (the demo course, translated); vision_play in en.
VoxCPM2 speaks those 8. Strings built at run time (scores, names, letters) and the full-course demo's per-learner slides are
not enumerable: the player falls back to the default voice (never silent) and keeps misses in window.__cloneVoiceMisses
(web); paste them into a JSON-lines file and pass --extra-texts to add them to the next render.

Render on the Spark (consent must be valid: commercial use, model training, course narration; samples unchanged)
  cd ~/code/gs-main && scripts/render_demo_voice.sh --voice channarith            # all clips; resumable
  scripts/render_demo_voice.sh --voice channarith --shard 0/2                    # another machine takes 1/2
  python3 -m tts_bakeoff.demo_voice.render publish                                # voices.json + index.json
  python3 -m tts_bakeoff.demo_voice.verify

Serving: Vultr Object Storage (S3 compatible), same bucket as the Android releases
  Where:  endpoint https://sjc1.vultrobjects.com, bucket salareen-prod (OBJ_ENDPOINT / OBJ_BUCKET, the names scripts/mobile_release.sh uses),
          prefix voice-assets/. Public URL: https://salareen-prod.sjc1.vultrobjects.com/voice-assets/<voice>/<lang>/<hash>.mp3
          plus voices.json and <voice>/index.json. Never in git, never in the web image.
  Clients: web reads NEXT_PUBLIC_VOICE_ASSETS_URL, frozen at `next build` (apps/web/Dockerfile ARG, default = the URL above; local dev
          leaves it unset and uses /voice-assets from apps/web/public). Mobile and Vision Play default to the same URL
          (apps/mobile/src/cloneVoice.ts; window.CLONE_VOICE_ASSETS overrides in Vision Play). A clip that 404s or a missing
          voices.json falls back to the default voice (never silent).
  CSP:    the site's Content-Security-Policy is only `frame-ancestors 'self'`, which does not restrict media or fetch, so nothing to
          allow. A pytest guard fails if someone adds media-src/connect-src/default-src without *.vultrobjects.com. Mobile fetches
          are not subject to CSP.

Upload (one-time setup, then per render). Needs the aws CLI (pip install awscli or brew install awscli) and credentials as env vars
(names only here): VOICE_ASSETS_ACCESS_KEY + VOICE_ASSETS_SECRET_KEY, or AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY, or an AWS_PROFILE,
or the cluster's OBJECT_STORE_ACCESS_KEY + OBJECT_STORE_SECRET_KEY, in the shell or config/local.env (only those keys are read). They
reach aws through its environment; they are never put on a command line, printed or committed.
  0. scripts/sync_voice_assets.sh status                     # shows endpoint, bucket, public URL, which credential NAME was found
  1. one-time CORS (bucket-wide, MERGES with existing rules; put-bucket-cors would otherwise replace them):
       scripts/sync_voice_assets.sh cors                      # prints the merged rules and the exact command
       scripts/sync_voice_assets.sh cors --apply [--origin https://other.example]   # origins default to salareen.com + www
  2. public read: nothing to do. `sync` gives every clip and the two json files an object ACL public-read (the APK upload does the
     same), so the rest of the bucket stays private. Optional alternative, a prefix-scoped bucket policy:
       scripts/sync_voice_assets.sh policy [--apply]          # Resource arn:aws:s3:::salareen-prod/voice-assets/*, merged with any existing policy
     Vultr documents bucket policies and shows a whole-bucket example; confirm the prefix scope after applying: voices.json is 200, a
     private key outside voice-assets/ is 403.
  3. after rendering on the Spark, copy the assets to the machine that has the keys and publish:
       rsync -a nvidia@192.168.1.107:~/voice-assets/ ~/voice-assets/
       scripts/sync_voice_assets.sh sync --dry-run             # prints every aws command, no credentials, no network
       scripts/sync_voice_assets.sh sync                       # clips, then each index.json, then voices.json last
     Headers: clips Cache-Control public, max-age=31536000, immutable and audio/mpeg; voices.json and index.json public, max-age=300.
     `sync` never deletes unless --delete-missing. Clip keys are a hash of the TEXT, not the audio: if you re-render the same sentence
     (new takes, cleaning, a tone) the file is re-uploaded but browsers that already cached it keep the old audio for up to a year.
     Rename the voice id for a re-render that must reach everyone at once.

Revocation: python3 -m tts_bakeoff.voice_clone.bakeoff revoke --speaker <id>, then
  python3 -m tts_bakeoff.demo_voice.render prune-revoked && scripts/sync_voice_assets.sh      # local assets and voices.json
  and for the bucket itself (works from any machine that has the keys, no local assets needed):
  scripts/sync_voice_assets.sh withdraw --speaker <id>                                       # shows the plan; no --yes = changes nothing
  scripts/sync_voice_assets.sh withdraw --speaker <id> --yes
withdraw first rewrites the remote voices.json with the voice inactive (clients stop looking it up within 5 minutes, immediately for
the web, which fetches voices.json with no-store), then deletes every object under voice-assets/<id>/. It refuses empty or odd ids.
Clips already played stay in browser and phone caches for up to a year (immutable); the bucket has no CDN in front, so there is nothing
to invalidate server-side. For a urgent case also rename the voice id.

Three voices, each in its own language (voices: channarith, wei-miao, wei)
  tts_manifest/voices.json lists three separate speakers, never merged, each with its own signed consent record and ids derived from the
  typed name (enroll_ui slugify): "Channarith" (channarith, English), "Wei Miao" (wei-miao, English) and "Wei" (wei, recorded in
  Cantonese, yue). The selector shows the name from the consent record plus the voice's own language: "Wei (Cantonese)",
  "Wei Miao (English)". Kept as separate ids on purpose: two people, two consent records, two named voices; nothing links them.
  Each voice speaks ITS OWN language(s) by default (the languages it was enrolled in). Other languages are cross-lingual and only
  happen when asked: scripts/render_demo_voice.sh --voice channarith --langs es,zh,vi  (or --langs all). Cross-lingual clips carry
  "cross_lingual": true in their sidecar and the listening lab badges them "cross-lingual". Folders starting with "_" (for example
  runs/<date>-clones/_cross-lingual-wei, where stray clips are set aside) are ignored by the lab and are never recreated by a run.
  Cantonese (yue, written colloquial Cantonese, Traditional characters) is in the manifest for all 361 English demo lines (the On the Go
  course plus Vision Play): tts_manifest/translations/yue.json, machine translations from Grok (grok-translation-v1, about $0.04 for all
  of it), every line status "unreviewed". 792 clips in the manifest; a voice renders only the languages it owns, so wei renders the 361
  Cantonese lines and the English voices the 361 English ones. Other demo languages for Vision Play (zh es vi th km sw hi) are
  English-only today; to add them: translations plan --langs zh,es,vi,th,km,sw,hi, then run, then manifest --offline.
  Cantonese cloning: VoxCPM2 lists Cantonese under Chinese dialects on its model card (the adapter declares yue). CosyVoice 2 does not
  list it, so the Cantonese lines render with VoxCPM2 only.

  Review by a native speaker (Wei, who recorded in Cantonese, reads her own language, so she is the reviewer):
    python3 -m tts_bakeoff.demo_voice.translations review-page --lang yue --out ~/review-yue.html    # one self-contained page, no network
    open the page, mark each line OK (or edit it, or "Needs a fix"), type her name, "Download my decisions"
    python3 -m tts_bakeoff.demo_voice.translations apply-review review-yue-decisions.json --reviewer "Wei"
    python3 -m tts_bakeoff.demo_voice.manifest --offline                                             # re-merge; "needs_fix" lines leave the manifest
  Statuses: unreviewed (machine), ok, fixed (corrected by the reviewer), needs_fix. Her progress is kept in the browser while she works.

Render (on the Spark; finished clips are skipped, so it can be repeated or resumed)
    scripts/render_demo_voice.sh --voice all              # every voice, its own language(s), one after the other under the GPU lock
    scripts/render_demo_voice.sh --voice wei              # just the Cantonese voice (361 lines)
    scripts/render_demo_voice.sh --voice channarith --langs all    # asks for cross-lingual clips on purpose
    python3 -m tts_bakeoff.demo_voice.render status       # clips per voice and language against the manifest
    python3 -m tts_bakeoff.demo_voice.render publish --reviewed-only    # index.json lists only reviewed translations (see below)
  --ref-mode auto|continue|reference chooses how VoxCPM2 hears the reference (docs/voice-cloning.txt); auto is right unless a listening
  test says otherwise. Every take is checked for audio length against its text and a take that cannot belong to it is rejected.
  Publish the Cantonese only after review: a machine-translated line spoken in a real person's voice, in public, can be wrong or odd.
  "publish --reviewed-only" (and "run --reviewed-only") leave clips whose sidecar says translation_status unreviewed out of index.json;
  the demos then use the default voice for those lines.


Home-page mascot narration (landing)
  The mascot on / explains each feature card with pre-rendered clips, not the browser's built-in voice. The lines live in
  apps/web/app/lib/landingVoiceLines.json (DNLandingHero.tsx imports it, tts_bakeoff.demo_voice.manifest lists it as demo "landing").
  Default voice = Salane (edge-tts en-US-AriaNeural): python3 scripts/render_landing_voice.py writes
  apps/web/public/landing-voice/salane/<lang>/<hash>.mp3 and index.json (small, committed; --check verifies). Needs edge-tts >= 7.3.1 and network.
  A visitor who picked a consented voice in the voice picker (profile menu) gets that voice's clip for the line when the voice has one
  (render it with scripts/render_demo_voice.sh, the manifest includes the landing lines); otherwise the Salane clip plays; the browser voice
  is only the last resort when a clip is missing. Nothing plays before the first press/tap/key on the page; reduced motion waits for a click.
  Compliance: edge-tts is an unofficial client of Microsoft's Edge Read Aloud service; the licensed route to the same voices is Azure AI Speech.
  The landing text is English only today, so only "en" clips exist; add rows to the JSON per language and re-run the render script.

Voice picker (profile menu)
  One dropdown: Default (auto), then a "Custom voices (AI-generated)" group (consented voices from voices.json that are active AND have
  clips for the site's current language, labelled "<name> (<language>) . AI-generated voice"), then the edge-tts voices with each real audio
  voice listed once (regional duplicates of the same neural voice are hidden unless the visitor already saved one). The choice is stored in the
  same key as the demo narrator selector (aoep_demo_voice). The Any/Female/Male filter is gone: the (F)/(M) in each option is the gender,
  and picking a voice keeps the stored gender in step, so existing visitors keep the voice they had.


Edge-tts tones and the tiered pre-render (backup path)
  Company voices (Channarith, Wei, Wei Miao) and the stock voices are the primary demo voices. The edge-tts voices in the account-menu picker stay
  LIVE, with an optional Tone (neutral, nine presets, thirteen professional/cute/anime mixes). The tone is edge-tts rate/pitch/volume; the numbers
  live in aoep_shared.tone_presets (a test keeps them identical to tts_bakeoff.voice_types). The speech gateway (/tts) and the course studio
  (/api/studio/tts) accept `tone`; the web sends the saved choice (localStorage aoep_demo_tone). A company voice cannot take a tone: that is a
  separate "stylized versions" consent scope nobody has signed, so the picker disables the Tone control for those voices.

  tts_bakeoff.demo_voice.edge_render builds a stored-clip set for later use (not uploaded; nothing in the product reads it yet):
    python3 -m tts_bakeoff.demo_voice.edge_render plan                 # tiered counts and sizes from the manifest and the picker catalog
    python3 -m tts_bakeoff.demo_voice.edge_render run --tiers 1        # tier 1 = Driver's Ed English; needs edge-tts >= 7.3.1 in that interpreter
    python3 -m tts_bakeoff.demo_voice.edge_render status --tiers 1     # read-only: done/total, rate, ETA
  Measured on this Mac (100 clips, tier 1 sample): 2 workers 2.2 clips/s, 4 -> 4.2, 8 -> 7.5, 16 -> 10.9, no throttling at any level; the
  default is 16 workers with at most 6 per voice. A voice that returns no audio at all (en-US-DavisNeural is no longer served) is probed first
  and skipped, not retried per clip. Tiers 2-4 (translated Driver's Ed, the other demos, the other languages) are planned but not rendered.

  COMPLIANCE: edge-tts is an unofficial client of Microsoft's Edge Read Aloud service. Serving its output live is one thing; keeping and shipping
  its audio as stored files is a bigger step. The licensed route to the same neural voices is Azure AI Speech (same voice names).
