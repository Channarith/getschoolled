COMPANY VOICE CLONING (owner + employees), VoxCPM2 and CosyVoice 2 on the DGX Spark

Rule: no consent record, no enrollment, no synthesis. Consent, samples and models stay in ~/voices on the Spark
(GS_VOICES_DIR), never in git (.gitignore covers /voices/ and *-clones/).

Flow
 1. Each person signs tts_bakeoff/voice_clone/CONSENT_FORM.txt (have counsel review it; the template is not legal advice).
 2. Record 30-60 s of clean speech in a quiet room, reading a script, and write down exactly what was said.
 3. On the Spark (python3 -m tts_bakeoff.voice_clone.bakeoff ...):
      consent --speaker alice --name "Alice Tran" --role employee --signed-form signed.pdf
      enroll  --speaker alice --audio alice.m4a --transcript-file alice.txt --lang en
      (consent stores the signed form's sha256; enroll trims, loudness-normalizes, checks length 20-90 s and SNR >= 20 dB)
 4. scripts/run_voice_clone.sh [OUT]  -> one gs_run.sh job per model (GPU lock, memory cap, CUDA required).
 5. python3 -m tts_bakeoff.lab --out OUT  -> clone voices are badged "CLONE: consented".
 6. Revoke: ... bakeoff revoke --speaker alice. Synthesis refuses at once; delete samples/models within 30 days (form clause 5).
Every synthesis re-hashes the signed form and every sample; edited or swapped audio is refused.

Browser enrollment (consent and recording in one page)
  On the Spark:   python3 -m tts_bakeoff.voice_clone.enroll_ui --root ~/voices        (binds 127.0.0.1:8780 only)
  On your laptop: ssh -L 8780:127.0.0.1:8780 <spark>   then open http://localhost:8780/
  (the microphone only works on localhost or https, so use the tunnel, not the Spark's IP address)
  Steps: name and role -> consent text (scrolls), four tick boxes, typed signature, and either reading a short statement
  aloud (kept as audio proof) or pointing at an already signed form on the Spark -> record 8 English lines (about 60 s;
  es/zh/vi/th/km are draft scripts for a native speaker to check) with a level meter and noise, clipping and length warnings
  -> the server normalizes and checks the result (20-90 s, SNR >= 20 dB) and registers it. The transcript is the script
  text, so nobody types it. "Enrolled voices" lists everyone, withdraws consent (type the name) and runs a test synthesis
  (VoxCPM2 or CosyVoice 2) when the host has CUDA; elsewhere it prints the exact scripts/run_voice_clone.sh command.
  Everything goes through registry.record_consent / add_sample, so the CLI gate is unchanged. The consent record keeps the
  timestamp, the sha256 of the exact consent text shown and of the spoken-statement audio. Requests from other sites or
  hosts are refused (Host and Origin checks plus a custom header).

Cantonese (廣東話) in the enrollment page
  Pick "廣東話" in the Page language box (top right). The whole wizard, the consent text (CONSENT_FORM.yue.txt), the four tick
  boxes, the spoken consent statement and the eight recording lines (written colloquial Cantonese, Hong Kong usage; line 5 is
  the six-tone drill 詩史試時市事; final particles 啦 喇 呀 㗎 噃 咩 呢) switch together. Typed names may be Chinese. Changing the page
  language while on the consent step clears the ticks, signature and recording, so a signature is always against the text shown.
  The consent record stores consent_language, the sha256 of the exact text shown and consent_text_draft = true.
  STATUS: the Cantonese consent text, statement and scripts are DRAFT TRANSLATIONS. The speaker (a native speaker) should read the
  whole text before agreeing, and counsel must review it, exactly as for the English template. Do not treat it as reviewed.
  Voice check: after enrolling, each recorded line is run through a speech recognizer (faster-whisper or openai-whisper large-v3,
  language "yue") and compared with the script as a character error rate (traditional/simplified folded when opencc is installed).
  It is WARN-ONLY: Cantonese colloquial speech is often written back as standard Chinese (嘅 -> 的) so a high error rate can be the
  recognizer, not the speaker; a flagged line asks the speaker to re-read it and never blocks enrollment. Skipped when no recognizer
  is installed or ENROLL_ASR=off; ENROLL_ASR=<spec> picks an engine (faster-whisper:large-v3, whisper:large-v3, fake:0 for tests).
  Cantonese synthesis support (model cards read 2026-10-25):
    VoxCPM2: README lists 粤语 (Cantonese) under "Chinese Dialect" among its supported languages; "input text in any of the 30
    supported languages and synthesize directly, no language tag needed". Cloning (prompt_wav_path + prompt_text) is demonstrated
    generally; the cards do not say it was tested on dialects, so judge a Cantonese clone by ear first. Cantonese is in the VoxCPM2
    adapter and in scripts/run_voice_clone.sh LANGS (default en,es,zh,yue,vi,th,km,sw,hi), text from tts_bakeoff/sentences/yue.jsonl
    (10 unreviewed machine translations). Write the sentences in Cantonese, not Mandarin.
    CosyVoice 2 (0.5B): Cantonese is NOT listed in its README; the dialect list (Guangdong, Minnan, Sichuan, ...) belongs to
    Fun-CosyVoice 3.0. So the adapter does not claim yue and the bake-off skips it (skipped_unsupported). Try Fun-CosyVoice 3.0 later.
  Edge-tts has Cantonese voices (zh-HK) but cannot clone; they are only a listening reference.

Cleaning (noise, clicks, hum) and best-of-N  [tts_bakeoff/voice_clone/clean.py; numpy only]
  Enrollment: the recording is high-passed (70 Hz), mains hum (50/60 Hz and harmonics) is notched, clicks are repaired and a MILD
  spectral gate is applied. The cleaned copy replaces the sample only if SNR did not fall, no clicks were added and the voice's
  tone colour (noise-corrected band profile) moved <= 1.5 dB; otherwise the original is kept and the page says why. The recording
  before cleaning is kept at samples/.raw/<name>.wav (removed together with the sample on re-record).
  The hard "too noisy" gate still uses the ORIGINAL SNR, so cleaning never rescues a bad recording.
  Synthesis: bakeoff run now makes --takes 3 per sentence (default), scores each (clicks, clipping, noise floor, gap hiss, hum;
  optional ASR word-error-rate with GS_CLONE_ASR=1 and openai-whisper, written but not run in CI), keeps the cleanest, then
  high-pass, hum notch, de-click, light gate, 8/25 ms fades and loudness normalize (tone-colour limit 2.5 dB). Scores per take are in
  <lang>/.raw/<id>.clean.json; the raw chosen take is <lang>/.raw/<id>.wav. Dot folders are hidden from the listening lab.
  Opt out: --no-clean, --takes 1, or GS_CLONE_CLEAN=0 / GS_CLONE_TAKES=1.
  Clean existing clips in place (originals kept; safe to repeat):
    python3 -m tts_bakeoff.voice_clone.clean --dir runs/2026-10-25-clones          # add --force to redo
    python3 -m tts_bakeoff.voice_clone.clean --in a.wav --out a.clean.wav          # prints a before/after table
  Limits: this removes steady hiss, hum and short clicks. It cannot remove a model artefact that is part of the word itself
  (a mispronounced or garbled syllable): re-synthesize (best-of-N helps) or report the sentence and word.

Models (license read 2026-10-25 from the model cards/repos recorded in tts_bakeoff/candidates.yaml)
  VoxCPM2: Apache-2.0, "free for commercial use". Its card adds: "Strictly forbidden to use for impersonation, fraud, or
  disinformation. AI-generated content should be clearly labeled" (so label cloned audio as AI-generated in the product). Zero-shot / "ultimate" cloning with transcript, 30 languages.
  CosyVoice 2 0.5B: Apache-2.0 weights; code repo is Apache-2.0 but its README and model card say "for academic purposes only and is intended to demonstrate technical capabilities"
  (a disclaimer, not a license term; ask counsel before shipping). Cloning: zero-shot (same language, needs transcript),
  cross-lingual (nine languages plus Chinese dialects; no km/vi/th/sw/hi in the base model, so it is bake-off'd on en,es,zh).
  Cloned voices carry the person's likeness: consent, not the model license, is the binding constraint.

Tones for cloned voices (professional, warm, calm, energetic, cute, anime, tough, heavy, light and the 13 blends)
  Same names as the edge-tts presets and blends (tts_bakeoff/voice_types.py). Two mechanisms, compared by ear:
    model  ask the model for the style. VoxCPM2 "controllable cloning": a description in parentheses before the text and
           the reference audio only, no transcript (with the transcript it continues the prompt and ignores style).
           CosyVoice 2: inference_instruct2(text, instruction + <|endofprompt|>, prompt wav); the documented instructions
           are Chinese, so English output may not keep the style. Neither was run against real weights when this was
           written; the listening set below is how we find out.
    dsp    post-process the neutral clone with ffmpeg: pitch (resample + atempo, so the formants move with the pitch;
           independent formant control needs WORLD or rubberband, not installed), tempo, a small brightness tilt, gain.
           Caps: +-3 semitones, +-15% speed, +-1.5 dB tilt, +-3 dB gain, so the voice stays recognisable. Works for any model.
  CONSENT: a stylized voice is a different use from the natural voice, so it needs its own opt-in. The base form covers
  commercial_use, model_training and course_narration only. tts_bakeoff/voice_clone/CONSENT_ADDENDUM_STYLIZED.txt is a
  separate, optional addendum (counsel to review); once signed:
      bakeoff grant-scope --speaker alice --signed-form alice-stylized-signed.pdf
  Without it every tone except neutral is refused, for both mechanisms. Withdraw only the addendum with
  `bakeoff withdraw-scope --speaker alice` (natural-voice consent stays); a full `revoke` stops everything. Speakers
  enrolled before this existed (including the owner) are neutral-only until they sign. The addendum's form hash is
  re-checked on every synthesis.
  Listening set (loadable in the lab; Voice type filter shows presets and blends, clones keep the CLONE badge):
      scripts/gs_run.sh --name clone-tones --gpu --timeout 7200 -- env PYTHONPATH=$PWD:$PWD/packages/shared/src \
        TORCHDYNAMO_DISABLE=1 ~/venvs/voxcpm/bin/python -m tts_bakeoff.voice_clone.bakeoff tones \
        --out runs/<date>-clone-tones --models voxcpm2 --langs en,es,zh --tones all --mechanisms dsp,model
  One neutral clip per sentence is synthesized on the GPU and every dsp tone is derived from it on the CPU; the model
  mechanism costs one GPU clip per preset (add --model-blends for the 13 blends too). Folders are
  <model>~<speaker>~dsp-<tone> and <model>~<speaker>~model-<tone>. From code (Say anything):
  tones.render_tone_clip(speaker, model, text, lang, tone, "dsp"|"model", out_wav) runs the consent gate first.

Say anything (type words, hear them in an enrolled voice)
  The enrollment page has a "Say anything" tab: pick an enrolled, consented voice, a model (VoxCPM2 or CosyVoice 2), a language and
  up to 500 characters; the clip plays in the page and can be downloaded. It goes through the same consent gate as everything else
  (no record or a withdrawn one = refused, and withdrawn voices stop playing), runs scripts/run_voice_say.sh under gs_run.sh (GPU lock,
  memory gate), refuses a second queued clip for the same voice and model, and shows waiting for GPU lock / running / done.
  VoxCPM2 compiles GPU kernels with Triton, which needs Python.h; without python3.12-dev the script sets TORCHDYNAMO_DISABLE=1.
  Every clip is stored under ~/voices/say/<speaker>/ with a .json sidecar (ai_generated: true, "AI-generated voice of <name>") because
  the VoxCPM2 license asks that generated audio be labelled. Command line: python3 -m tts_bakeoff.voice_clone.bakeoff say ...

Voice profile: several samples per speaker, the best one per language (tts_bakeoff/voice_clone/profile.py)
  A speaker can have several enrolled samples (languages, sessions). Every sample records its language, length, SNR, whether the cleaned
  copy was kept (PR #806: the recording is kept as it was if cleaning would change the voice), the language and sha256 of the consent text
  the speaker saw, and when it was enrolled.
  Each speaker speaks their OWN language(s) by default: the bake-off, tones and the demo render use the languages a speaker was enrolled
  in (most clean audio first), so "wei" (Cantonese) speaks Cantonese and shows up under Cantonese in the lab, and "wei-miao" and
  "channarith" speak English. An explicit --langs overrides (--langs all = en es zh yue vi th km sw hi); scripts/run_voice_clone.sh
  passes --langs only if LANGS is set. A clip in a language the voice was not enrolled in is cross-lingual: its manifest row carries
  "cross_lingual": true and the lab badges it. Lab clone labels read "Wei (Cantonese) - voxcpm2".
  For each sentence the adapter uses the sample that suits the sentence's language, one model load for all languages. Fallback order:
    1. same-language   a sample in the target language (a Cantonese reference for yue) with the transcript that was actually said
    2. close-language  yue <-> zh (same script, shared sounds, different tones and words)
    3. cross-lingual   the cleanest sample in any other language
  Inside a tier: a short reference clip beats a long session recording, then highest SNR (cleaned copies by their cleaned SNR), then the
  longest. Consent, scope and every sample hash are re-checked on every pick. Clone bake-off, tones, say-anything and the demo render all
  call synth.build_adapter, so all of them get this. Stylized tones still need the stylized_versions scope (granted to nobody yet).
    python3 -m tts_bakeoff.voice_clone.profile choose --speaker wei --lang yue

Reference clips and reference mode (why speech sometimes does not follow the text)
  The enrollment page joins the 8 prompt recordings into one ~60 s sample with a joined transcript. VoxCPM2's default "continue" mode
  (ultimate cloning) treats the reference audio as the start of the speech and needs its EXACT transcript; a 60 s concatenation whose
  transcript is not word for word what was said, or a Cantonese reference with English text, makes it log "Badcase detected,
  audio_text_ratio=6.4, retrying" and produce speech that drifts from the text. CosyVoice 2 wants a prompt under about 30 s.
  Fix: one short reference per language. The page saves every prompt as its own take (raw/<lang>/<lang>-N.wav) and the prompt text is
  known, so profile refs picks ONE clean single-utterance take of 5-20 s (highest SNR, closest to 11 s, not clipped; with GS_CLONE_ASR=1
  a take whose round trip does not match its prompt is rejected) and registers it with role "reference", the exact prompt text and
  transcript_exact true. Enrollment now does this automatically; for voices enrolled before, run once per speaker on the Spark:
    python3 -m tts_bakeoff.voice_clone.profile refs --speaker wei --dry-run     # shows the take it would use and what it skipped
    python3 -m tts_bakeoff.voice_clone.profile refs --speaker wei               # also: --speaker wei-miao, --speaker channarith
  Reference clips are cut from the same takes as the session recording, so they do not count toward the fine-tune minutes.
  --ref-mode auto|continue|reference (bake-off run/tones/say, render_demo_voice.sh; env GS_CLONE_REF_MODE):
    continue    reference audio + its exact transcript: only for the SAME language as a reference with an exact transcript
    reference   audio only (VoxCPM2 reference_wav_path), no prompt text: for another language, or whenever the transcript may not match;
                the voice carries over and the words come only from the text
    auto        (default) continue only for a same-language, exact-transcript, short reference; otherwise reference
  The mode used is printed per sentence ("[voxcpm2] ref-mode=reference lang=en reference=ref-yue.wav") and stored in each clip's row.
  Sanity check on every take (clean.py, the best-of-N scorer): audio length against the text's normal speaking time (characters per
  second per language); a take more than 2.5x too long or under 0.4x is rejected, and with GS_CLONE_ASR=1 a whisper round trip with a
  large error (en es zh yue vi hi) rejects it too. If every take fails the clip is not written and the run records a failure.

CosyVoice 2 setup check
  scripts/check_clone_models.sh (read-only) runs tts_bakeoff.voice_clone.doctor under each model's own Python and prints what is missing and
  the fix command, then the tail of the last synth-*.log files. A likely cause of a short failed CosyVoice 2 log: the adapter's default
  model_dir was the relative path pretrained_models/CosyVoice2-0.5B; the run starts in the repo checkout, where it does not exist, so the
  model tried to download that string as a model name. It is now <repo>/pretrained_models/CosyVoice2-0.5B (env COSYVOICE_MODEL_DIR),
  passed explicitly by run_voice_clone.sh, and the adapter check reports missing weights. CosyVoice 2 has no Cantonese: it is skipped
  for yue (the cloning notes on PR #811), so "wei" renders with VoxCPM2 only. Whether ~/code/CosyVoice, its .venv and the weights exist on
  the Spark is not known from here: run the script and read its fix lines.

Zero-shot cloning is not training
  What runs today (VoxCPM2 and CosyVoice 2) hears one enrolled sample as a reference and imitates it. Nothing is trained and no
  model weights change, so one minute of clean speech is enough to start; more and cleaner samples improve it only a little.
  Fine-tuning (LoRA or full) does change the model for one speaker, and needs much more audio. What the docs say (read 2026-10-25):
    VoxCPM2   README: "with as little as 5-10 minutes of audio" you can adapt to a speaker, language or domain. Fine-tuning Guide
              (voxcpm.readthedocs.io): 3-30 s per clip, 5-50 clips to clone a single speaker with LoRA, 30-50% of samples with a
              reference clip, JSONL rows {audio, text, duration, dataset_id}, the encoder works at 16 kHz.
    CosyVoice 2   the README states no minimum; its training recipes are written for large corpora. Treat as unknown, plan on at least the
              VoxCPM2 numbers and expect to need more.
  Each enrollment today is one concatenated sample of about 60 s per language, so a speaker has about 1 minute per language.
    python3 -m tts_bakeoff.voice_clone.profile report [--speaker wei-miao]     # clean minutes per language, SNR, cleaned count, consent
                                                                               # language, and how far each is from the VoxCPM numbers
    python3 -m tts_bakeoff.voice_clone.profile prep --speaker wei-miao --model voxcpm2 --out ~/voices/wei-miao/finetune
  prep is a stub: it writes a manifest.jsonl from consented samples and flags those outside 3-30 s (they would need segmenting with a
  forced aligner, not built). It refuses to write until the minutes are there (--force writes anyway) and it never trains anything.
  What to record next to reach fine-tune readiness: about 10 minutes of clean speech per language you want fine-tuned (Cantonese
  for wei, English for wei-miao and channarith), in 5-10 sessions of 60-90 s each, read from varied text, quiet room, same microphone,
  the transcript saved exactly. Add each one with: python3 -m tts_bakeoff.voice_clone.bakeoff enroll --speaker wei
  --audio session2.m4a --transcript-file session2.txt --lang yue (the enrollment page records one 8-line set per language today).

Faster, resumable clone runs (v0.97.58)
  Re-running is cheap: a clip that exists (not tiny) with an "ok" manifest row is skipped; --force regenerates. A failed or truncated clip is redone.
  scripts/run_voice_clone.sh OUT [--speakers a,b] [--force]      LANGS=all (every language the model supports) or a comma list
  Workers: GS_CLONE_WORKERS / --workers N (default 2) shard the (speaker, language) units across N processes under the ONE gs_run lock and job
           (the one-job-per-name rule and the GPU lock are unchanged). N is reduced to what fits above the 16 GB gate (about 10 GB per worker; --strict-workers
           refuses instead). One model load per process; synthesis is serialized per process (one GPU) while the CPU stage (scoring, cleaning) of a clip
           overlaps the next synthesis (--post-threads, default 2). Whether N > 1 is faster on a single GPU must be measured on the Spark:
           scripts/measure_clone_workers.sh 1 2 3      (same clips for each N, prints seconds, clips/min and speedup)
  Languages (read from the model cards 2026-10-25): VoxCPM2 31 = ar my zh da nl en fi fr de el he hi id it ja km ko lo ms nb pl pt ru es sw sv fil th tr vi + yue.
           CosyVoice 2 9 = zh en fr es ja ko it ru de (the card text is shared with Fun-CosyVoice 3.0 and the paper evaluates zh/en/ja/ko, so fr/it/ru/de
           are unverified; no Cantonese). Sentences: the same 3 per language as the edge-tts lab (tts_bakeoff/sentences, 75 languages). A voice's own
           language(s) run by default; --langs all or an explicit list add the others, labelled cross-lingual.
  Progress:   python3 -m tts_bakeoff.voice_clone.bakeoff status --out OUT       (read-only: per voice and language, bar, workers, ETA, GPU lock, and a
              last line RUNNING / DONE / INCOMPLETE). The run writes OUT/progress.json and OUT/progress/worker-N.json; the lab shows them too.
  Lab:        python3 -m tts_bakeoff.lab --out OUT    rescans the folder by itself every 20 s while a run changes it (or press "Refresh clips"): no restart
              for new clips. The language picker shows voices and clips per language, and hides languages without clips behind "Show languages without clips yet".
