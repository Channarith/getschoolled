AOEP - DESIGN & ARCHITECTURE
============================
Agentic Online Education Platform. This is the text source-of-truth for the
system design; GitHub-facing rendered diagrams live in the README as mermaid,
and a compiled visual reference lives in docs/architecture.pdf (frontend,
backend, accounts, data flow, network traffic, live classes, deployment).

No-markdown house rule: this file is plain text on purpose. Diagrams here are
ASCII; the README keeps the rendered GitHub version; the PDF and its PNGs under
docs/diagrams/architecture/ are generated from code by
scripts/build_architecture_pdf.py (re-run it after any architecture change).

-----------------------------------------------------------------------------
1. SYSTEM CONTEXT (who uses it)
-----------------------------------------------------------------------------
  Free learner / visitor ....... browse catalog, ad-supported watch, live class
  Paid member (Pro/Premium) .... ad-free watch, full catalog, rewards
  Parent / account holder ...... many learner sub-profiles, mastery, portfolio
  Student sub-profile .......... the person actually taking a class
  Educator / institution ....... Human-in-the-Loop review (co-teach / co-grade)
  Platform admin / ops ......... feature flags, versions, data-mining insights
  Partner / integrator ......... LMS/LTI, finance, cloud connectors, webhooks

4. KEY DATA FLOWS
-----------------------------------------------------------------------------
4a. Ask the AI teacher (grounded, optionally human-reviewed)
    web -> orchestrator /api/sessions/{id}/ask
         -> RAG retrieve (curriculum/sample-curriculum)
         -> Tutor compose answer grounded in passages
         -> groundedness guard (flag unsupported claims, confidence)
         -> HIL: should_escalate(confidence,risk,autonomy)?
               yes -> ReviewQueue (educator /console approves/edits) -> student
               no  -> answer returned with citations + confidence

4b. Post-class survey -> multi-dimensional data mart (data mining)
    admin enables engagement.post_class_survey (flag, memory)
    web /class "Finish" -> GET /survey/post-class (gated) -> modal
    submit -> POST /survey/post-class -> SurveyStore
    admin GET /admin/survey/insights -> OLAP cube (course x class_type x rating)
          + mined free-text suggestion themes

4c. Ad decisioning + revenue (monetization)
    Video ad breaks (pre/mid-roll, VAST/VMAP), tier-gated:
      web /watch, /class, Drive Mode -> curriculum GET /courses/{id}/ad-breaks?tier=
        (Drive audio courses aren't in the catalog -> billing GET /ads/plan?tier=)
      tier in {pro,premium} (VIP; admin defaults VIP) -> ad-free (empty plan)
      else -> pre-roll + capped mid-rolls; VideoAdBreak.tsx plays them (real
              <video>, skip timer, click-through; house media falls back to a
              branded card). class = pre-roll on start + mid-roll every 5 slides;
              Drive = one-time audio pre-roll per session.
    Display ads: web AdSlot (home) via billing GET /ads/slot; mobile AdMob
      banner (Home, Browse) + interstitial (mid-lesson) on iOS + Android.
    Revenue accounting: web + mobile fire impression/click beacons ->
      billing POST /ads/impression|/ads/click -> AdRevenueLedger (aoep_shared/
      ad_revenue.py: CPM/CPC by network+format, eCPM, CTR). Admin console
      "Ad Revenue" reads billing GET /ads/revenue. Estimate + funnel only; the
      network's own dashboard is the payout of record.
    Testing: append ?ads=1 to any web URL to force ads on an ad-free/admin
      account, or sign in as a Standard-tier account (qa1/qa2).

4d. Rewards (points -> prizes)
    identity set_status(passed) -> PointsLedger += points_for_completion
    GET /rewards -> balance + ledger; POST /rewards/redeem -> voucher / raffle

4e. Personalization (Foresight)
    curriculum POST /recommend(student profile) -> Foresight engine
         (attention, multimodal fuse, router, pattern attention, multi-head)
         -> ranked recommendations + skill gaps + adapted difficulty

4f. Live class (group / solo 1:1) lifecycle
    web/mobile -> orchestrator /api/live-rooms/{id}/join (carries the learner's
         language) -> mint LiveKit no-publish token (single-speaker mutex);
         first learner = admin. Room state persists to Redis so every replica
         agrees. A tick loop (any client, 8s) auto-starts when the room is full
         or 5 min past the scheduled time, auto-advances slides on a dwell timer,
         and AUTO-ENDS at the allotted time with a courteous multilingual "class
         complete" farewell + countdown. Q&A: raise hand -> host/AI grants the
         floor -> publish token issued (one speaker at a time). Solo 1:1 is the
         same room scaled to a single learner seat (open-ended, no auto-end).

4g. Language follows the learner (course in their language)
    identity persists preferred_language; GET /auth/me returns it. Web + mobile
    LocaleProvider adopts it on any device and saves picker changes back
    (POST /account/language). The Tutor answers each learner in that language
    (aoep_shared.languages.language_name -> "Respond entirely in <language>").

5. ADMIN / OPS SURFACE
-----------------------------------------------------------------------------
  Feature flags (memory): public GET /flags/evaluate, /flags/{key};
    admin (X-Admin-Secret == ADMIN_SECRET) PUT/override/reset.
    Catalog ~30 flags across engagement/data/access/monetization/ai/ux/ops.
  Version visibility: every service GET /version (version, git_sha, build_time,
    api_version, deploy_mode); GET /__meta (route index for automation).
    Web /admin "System & Versions" panel aggregates + flags version drift.
  Automation hooks (gated by ADMIN_SECRET AND ENABLE_TEST_ENDPOINTS):
    POST /admin/test/reset|seed for deterministic E2E setup.
  Observability (every service, dependency-free; local + cloud):
    GET /metrics            Prometheus exposition (perf, memory, requests, latency)
    GET /telemetry/summary  perf + memory/runtime (RSS/CPU/GC/threads) + counts
    GET /telemetry/errors   recent exceptions w/ traceback + request id (RCA)
    GET /telemetry/logs     recent structured events
    Request middleware stamps X-Request-ID + Server-Timing and records per-route
    latency/error stats; optional Sentry/OTLP export via env when libs present.
    Web /admin "Observability & Telemetry" panel aggregates all services.
  QA: qa/stress.py (all 8 services; health/version/__meta + endpoint scenarios),
    qa/regression.py (pytest+coverage, web typecheck/lint, stress smoke).

6. DEPLOYMENT TOPOLOGY (dual/triple mode)
-----------------------------------------------------------------------------
  DEPLOY_MODE=local  docker compose; mocks/sandboxes; everything offline-runnable
  DEPLOY_MODE=cloud  Kubernetes + GPU pool; real LLM/speech/vision; Stripe; S3
  DEPLOY_MODE=edge   on-device/humanoid image (apps/agent-runtime/edge); offline
  Each capability (llm/speech/vision/media/object_store/payment/ocr/...) can be
  overridden independently by <COMPONENT>_MODE without forking code, e.g. keep
  biometrics local even in cloud for compliance.

  Cloud is deployed on Kubernetes (currently Vultr Kubernetes Engine, VKE).
  Manifests: infra/k8s (kustomize base) + infra/k8s-vke (Vultr overlay). Images
  are built/pushed and the deployments rolled by .github/workflows/deploy.yml
  (Vultr Container Registry, sjc.vultrcr.com/salareen). In-cluster every service
  listens on :8000 and is addressed by Service name; the browser reaches them
  through one nginx Ingress.

    Cloudflare DNS + TLS (salareen.com / api.salareen.com)
                         |
            +------------v-------------+
            |   nginx Ingress          |  host + path routing
            |   - / -> web             |  cookie session affinity (pins a
            |   - /api/ -> orchestrator|  learner to the orchestrator replica
            |   - /<svc>/ -> <svc>     |  that holds their in-memory session)
            |   cert-manager TLS       |
            +------------+-------------+
                         |  (namespace: aoep)
   +----------+----------+----------+----------+-----------+
   |          |          |          |          |           |
   v          v          v          v          v           v
  web      orchestr.  curriculum  identity   memory   integrations  ...
  x3       x3         x3          x3         x3        x3            (speech,
  HPA/PDB  HPA/PDB    HPA/PDB     HPA/PDB    HPA/PDB   HPA/PDB        perception,
  :8000    :8000      :8000       :8000      :8000     :8000          billing :8000)
       \        \        |          /          /          /
        \        \       v         /          /          /
         +--------+--> Redis (rate-limit/cache) ; Postgres+pgvector ; Object Storage
  orchestrator --> vLLM / LLM (GPU pool; deterministic grounded fallback if absent)

  HA defaults (infra/k8s): minReplicas 3 across zones (pod anti-affinity +
  topology spread), HPA on CPU/memory, PDB minAvailable 2 (N-1 under drains),
  rolling updates with maxUnavailable 0 + preStop drain. CI/CD: deploy.yml runs
  on manual dispatch or push-to-main (AUTO_DEPLOY var); needs the registry creds
  + kubeconfig secrets.
